## 游戏可以删掉的绕路

以下是 v0.2 接入时各游戏手写的通用代码，v0.3 起内核已经提供。迁移留给游戏侧的会话，每项都是可选的。

**飞船**
- 比较 `operations` 长度判断是否执行：改用 `StepResult.outcome` 与 `recordId`。
- 重算候选来给请示分类（预算、能力、模型）：改用 `request.subject.cause` 与 `code`。
- 决策路由器让每条记录都写成路由器名：路由时在决策上写 `provider`。
- 重置时逐个停插件、手动安排 `ship-world` 最后停：改用 `plugins.stopAll()`。
- README 写着固定在 `7724010`，实际通过软链接使用最新内核，需要更正。

**弹幕**
- 决策失败后用 `revise()` 加手动重试：改用 `onDecisionError: 'wait'`。
- 实际决策期限是 2.5 秒的观测有效期，而配置的决策超时是 10 秒：两者应对齐。
- 每个动作步原来观测 3 次，每次排序约 1300 发子弹：内核已降到 2 次，不用改代码。
- 退出时 stop、再 step、再逐个停插件：改用关停配方与 `stopAll()`。
- README 与 deploy 文档说两处内核修复尚未提交：它们已在 `7ca21b5`，`release-manifest` 对内核文件的哈希绕路可以去掉。

**浇给**
- `Deciders` 里的信号量、共享调用预算和每角色在途保护：改用 `limitDecider(jev, { concurrency, maxCalls })`；每意图单飞由 Hub 保证。
- 每回合给出错的 Run 发 fact 回应解冻：改用 `onDecisionError: 'wait'`。
- 比对 `operations`、按标签扫描决策记录：改用 `StepResult` 的 `decisionId`、`recordId` 与 `DecisionStore.get()`。
- 合成的等待被记成 Jev：在合成决策上写 `provider`。
- 用 hold/pass 候选压住内置 `ask`：可以直接 `builtins: { ask: false }`。
- 512 字符上限导致的 `invalid-contract`：自由文本现在是 4096。
- 手写关停：改用关停配方。
- 单局 13 MB 导出与 Ultra 模式的无界增长：`recordFacts: false` 与 `runtime.prune()`。
- 长时间空闲 Run 的单步开销：内核已与历史无关，不用改代码。
- 手写 JSON 检查点：可以把现有 PostgreSQL 适配器接到带数据目录的 PGlite 上，已验证跨进程可读回。

## 内核仍然不做的

- 帧请求合并与丢弃过时帧（弹幕）：调度仍归宿主。
- 弹幕服务端手工构造 `BoundAction` 转发给 Jev：记录里的请求与 Jev 实际看到的不同，重评无法复现。这是游戏架构的选择。
- 用 Policy 做候选筛选（浇给的 80/20 规则）：Policy 现在能看到本轮全部候选，但筛选与授权分离需要单独设计。
- `HumanInbox` 的增长：宿主应在处理后 `acknowledge()`。
