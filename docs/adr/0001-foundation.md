# ADR 0001 — 插件化嵌入内核，而不是新建一个万能 Agent 平台

状态：本次实现采用。日期：2026-09-19。

## 背景

同一个 CognitiveHub 应可被人形机器人、多机器人管理平台及其他软件产品接入。能力通过插件加入；人类可以提供慢思考；Jev 是首个快速判断后端，而不是不可替换的内核。

仓库已有蓝图采用 TypeScript/Bun 方向，讨论中也出现过 .NET 宿主建议。本次保留 TypeScript 公共契约，优先可移植 Web API 与 Node 22 离线验证，避免同时写两个未经验证的运行时。C# 是重要宿主接入方向，不假称本次已有 SDK。

## 决策

1. 一个小包，逻辑分层，不提前拆成多服务或复杂 monorepo。
2. 零运行时依赖；直接适配 Jev 已公开 HTTP 协议，不绑定 experimental AI SDK。
3. 借鉴 dsh 的依赖与生命周期，独立实现受信任模块宿主，不复制它的整个产品。
4. 有界 propose/execute/reconcile 为首版入口；宿主拥有调度、正式任务和强制安全边界。
5. 直接端口注入和插件贡献可以共存；不能把最终 Policy 暴露为普通插件可覆盖的授权后门。
6. 默认 dry-run；真实提交显式 opt-in，仍需最新宿主授权。
7. 内存适配器用于模拟/开发，明确拒绝把其包装成持久化工作流保障。
8. 保留原始蓝图，另建当前实现文档与路线图，避免覆盖设计历史。

## 代价

暂不提供 Cordis 插件兼容、包市场、热代码升级、服务进程、.NET SDK 或跨进程恢复。宿主必须实现状态与授权端口，能力作者必须给出验证和查询语义。

好处是首版可以实际运行并测故障路径，之后扩展数据库、远程执行和其他语言 SDK 时有明确契约，而不是先堆抽象名称。
