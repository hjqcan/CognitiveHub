v0.3 候选，按价值排序：阶段 A 的真实宿主只读接入；取消/补偿端口；outbox 与 journal retention；人工请求持久化；C# 接入端。以下阶段保持原有描述。

## 阶段 A：一个真实宿主的只读/旁路接入（v0.2 之后）

接入 RMS/RBS 现有状态，不下发真实运动。将实际异常整理成 Observation，人工评估候选召回、决策建议和拒绝行为。v0.3 已提供内核侧支持：`approval: 'advisory'` 的旁路 Run 只提案与预检、从不派发，`compareAdvice()` 与 `scripts/replay.mjs --labels` 按平台实际决定给出一致率与召回率（步骤见 `docs/integration.md`）。剩下的是真实宿主的只读状态适配器与标注数据，需要平台访问。

验收：不改认知内核即可更换适配器；Hub 关闭时原平台照常工作；敏感数据和权限不进入模型；不能把“旁路建议合理”当作“执行一定成功”。

## 阶段 B：可靠执行基础

已完成：单进程重启后的记录核对、插件版本固定与在途记录重新绑定。剩余：PostgreSQL journal、事务 outbox、跨进程所有权租约、自动恢复循环、人工请求持久化、鉴权与审计。

验收：在 claim、发送、回执和验证各阶段故障注入；重启后不会重复产生副作用；未知请求可按稳定幂等键核对；不宣称没有执行端去重就能 exactly-once。

## 阶段 C：受限真实操作

选择低风险、可检查、可停止的正式任务。加入权威执行网关、条件写入、权限变更、维护窗口及操作预算。物理风险由独立控制与安全机制约束。

验收：不越权、不争夺原平台控制权、不把接受当完成；减少无效处理和人工负担；完整覆盖取消、恢复、并发与回滚限制。

## 阶段 D：插件生态与跨宿主 SDK

协议版本管理、.NET SDK、远程插件 worker、签名/来源治理、声明式 profile、MCP 桥、记录/回放与观察面板。

验收：数字产品、人形机器人、平台管理层主要通过不同插件组合接入，而不是各复制一份 Hub。第三方代码隔离需要真正的进程/部署权限边界。

暂不排期：任意自然语言到正确计划、模型自主安装插件、机器人端到端控制、在线自动修改授权规则。
